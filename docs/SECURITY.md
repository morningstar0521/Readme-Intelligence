# Security

README content is untrusted input. This document lists each threat from the PRD security spec, the
mitigation in the code, and the test that proves it.

| Threat | Mitigation | Where | Test |
|---|---|---|---|
| XSS through raw HTML | `rehype-raw` then ALWAYS `rehype-sanitize` with a strict allow-list before any other HTML processing. Post-processing only adds trusted values. React renders the sanitized tree as elements (no `innerHTML`, so no browser re-parse / mXSS). | `core/src/render/pipeline.ts`, `sanitizeSchema.ts`, `web/components/markdown/MarkdownView.tsx` | `tests/security/xss.test.ts`: 50 payloads, each rendered alone, all together, and nested in lists / quotes / tables |
| `javascript:` / `data:` URLs | Sanitizer protocol allow-list (`href`: http, https, mailto; `src`: http, https, data) plus `resolveUrl`, which strips control characters before reading the scheme and narrows `data:` to `image/(png\|jpeg\|gif\|webp)` | `render/resolveUrls.ts` | `resolveUrls.test.ts` (obfuscated variants), every XSS payload asserts no `javascript:` / `vbscript:` / `data:text/html` / `data:image/svg` in any tag |
| Event handlers (`onerror`, `onclick`...) | Not in the allow-list, removed | `sanitizeSchema.ts` | every payload asserts no `on*=` attribute |
| `script`, `style`, `iframe`, `object`, `embed`, `form`, `input`, `link`, `meta`, `base`, `svg`, `math`, `template`, `noscript`, `textarea` | Dangerous containers are stripped with their content; other unknown tags are unwrapped. `input` survives only as a disabled checkbox directly inside a GFM task-list item. No iframes in v1. | `sanitizeSchema.ts` (`strip`, `ancestors`, `required`), `pipeline.ts` | XSS assertions on forbidden tags |
| CSS injection via `style` | `style` is never allowed. Only `align` on p, div, img, td, th (and headings, see relaxations) and `width` / `height` on img | `sanitizeSchema.ts` | payloads with `style=` (`<div style=...>`, `<kbd style=...>`) |
| DOM clobbering via `id` / `name` | User ids and names are prefixed `user-content-`. Heading ids are generated by us. In-page anchors resolve both forms. | `sanitizeSchema.ts` (`clobber`), `web/lib/jump.tsx` | "prefixes user-supplied ids" test |
| `target="_blank"` abuse | All external links get `target="_blank"` and `rel="noopener noreferrer nofollow"`; user `target` is dropped | `pipeline.ts` | "adds rel=..." test |
| SSRF through the GitHub proxy | Input host allow-list (github.com, www.github.com, raw.githubusercontent.com); IPs, localhost, ports, credentials, other hosts and dot segments rejected. The server only calls `api.github.com` and `raw.githubusercontent.com` with URLs built from validated owner / repo / ref / path, and checks the host again before every fetch. | `github/parseUrl.ts`, `github/fetchReadme.ts` | `github.test.ts` ("rejects invalid hosts, IPs and localhost", "rejects path traversal", "rejects invalid input without any network call") |
| SSRF / abuse through the repo snapshot route | Same owner / repo / ref / path validation (`validRepoTarget`, no `..` segments). The server only calls `api.github.com/repos/{owner}/{repo}/git/trees/{ref}` and `raw.githubusercontent.com/{owner}/{repo}/{ref}/{path}` for paths taken from that tree. At most 60 files, 200 KB each, 3 MB total, 10 s timeout, 6 parallel requests. Repository files are parsed as text, never executed or rendered as HTML; the snapshot is validated with Zod in the browser. | `repo/fetchRepo.ts`, `repo/select.ts`, `app/api/github/repo/route.ts` | `repo-checks.test.ts` ("reads the tree and the selected files from GitHub hosts only", "rejects invalid targets without any request", "maps 404 and rate limits", "records skipped files and keeps the truncated flag") |
| Untrusted pull requests in the drift workflow | Uses the `pull_request` trigger (not `pull_request_target`), so fork PRs get a read-only token and no secrets. The checker code runs from the base commit; the PR head is checked out without credentials and only read as text (no install, no scripts). Token permissions are `contents: read`, `pull-requests: write`. | `.github/workflows/readme-drift.yml` | manual (workflow review) |
| Resource exhaustion | Input over 1 MB is truncated (local / paste) or rejected with TOO_LARGE (GitHub). Blockquote markers capped at 20 per line, indentation at 120, list nesting at 20. Post-processing walks are iterative. Fetch timeout 10 s. | `parse/parseMarkdown.ts`, `fetchReadme.ts`, `pipeline.ts` | `analyze.test.ts` (1 MB random text, 5,000 nested quotes, 500 nested lists, fuzz), `github.test.ts` (TOO_LARGE) |
| Secret exposure | Secret-looking env values are replaced with `••••••••` inside core, so the original never reaches the UI or the JSON export. `GITHUB_TOKEN` is read only in the API route and sent only to GitHub. | `extract/env.ts`, `app/api/github/readme/route.ts` | `env.test.ts` ("never leaks the original secret"), `analyze.test.ts` (JSON export), e2e test 1 |
| Command execution | Nothing is executed. Commands are copy-only; risky ones get a warning icon. | `extract/commands.ts`, `CommandsCard.tsx` | `commands.test.ts` (risky flags) |
| Remote image tracking | Images load from their original host with `referrerpolicy="no-referrer"` and a global `Referrer-Policy: no-referrer`. Settings shows "Images are loaded from their original URLs" and a "Block remote images" toggle (click-to-load per image). | `SafeImage.tsx`, `SettingsMenu.tsx`, `next.config.mjs` | manual |
| Local content leaving the browser | Local files are read with `File.text()` and passed to the viewer through `sessionStorage` (same tab). No request carries the content. | `Landing.tsx`, `lib/storage.ts` | e2e test 7 |
| Analytics data boundary | When enabled on a Vercel deployment, Vercel Web Analytics is anonymous and cookieless. The app sends page-usage metrics only; local Markdown, pasted text, README contents, extracted values, and secrets are not sent as analytics data. Analytics is disabled for local non-Vercel runs. | `app/layout.tsx`, Vercel Web Analytics | manual: inspect network payloads and dashboard events |
| CSP | `default-src 'self'; script-src 'self' 'nonce-…' 'strict-dynamic'; style-src 'self' 'unsafe-inline'; img-src 'self' https: data:; font-src 'self'; connect-src 'self'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'` | `apps/web/middleware.ts` | e2e tests run against the production build with this CSP |

## Documented relaxations

| Item | PRD | Implemented | Reason |
|---|---|---|---|
| `script-src` | `'self'` | `'self' 'nonce-<random>' 'strict-dynamic'` (+ `'unsafe-eval'` and `ws:` in development only) | The Next.js App Router injects inline bootstrap scripts. A per-request nonce allows exactly those; `'unsafe-inline'` is never used for scripts. |
| `style-src` | `'self' 'unsafe-inline'` | same | Shiki emits colour variables in `style` attributes on its own output (never on README HTML). |
| `font-src` | not listed | `'self'` | `next/font` self-hosts Inter and JetBrains Mono. |
| `align` on headings | not listed | allowed with values left/right/center/justify | `<h1 align="center">` is very common in READMEs; `align` cannot carry script or CSS. |
| `<details open>`, `<ol start>`, `<abbr title>`, `<q cite>` | not listed | allowed | Plain presentational attributes used by GitHub READMEs. |
| Link colour token `--link` | not listed | added | The accent colour is below WCAG AA for small text on the dark background, so links use a lighter shade of the same hue in dark mode. |

## Reporting

This is a personal project. Open an issue for any bypass of the sanitizer; include the Markdown that
reproduces it, after removing secrets and private content. Extraction problems can be reported through
the public feedback issue template.
